# Project state and engineering handover

Prepared 16 November 2026 for the next project maintainer.

## Executive assessment

The project is now a quantitative research platform with an LSTM model, rather than the original Python stock prediction prototype. Rust handles validated data, features, runtime inference, simulated execution, backtesting and APIs. Python handles model training and ONNX export. A React inspector exposes research artifacts and forecasts; a newer market dashboard adds public crypto observation, securities catalogues and daily forex reference charts.

Alpaca live ingestion is connected to forecast inputs. Forecasts run on request using completed, first-published regular-session minute bars and a compatible model. This does not establish live-provider deployment acceptance or predictive performance. The application remains a research simulator and does not place live orders.

The immediate handover priority is to reconcile stale documentation and validate the intended deployment and real-data model workflow. More dashboard coverage should not be mistaken for more trained-model coverage.

## Drift from the original project

The original scope is described in `Docs/00-AUDIT.md`: Python acquisition and features, a PyTorch model, basic evaluation/backtesting and disconnected entry scripts. The migration plan deliberately expanded this into a reproducible research platform with Rust runtime ownership, a unified CLI and versioned artifacts. That architectural expansion is intentional.

Three later changes broaden the scope further:

1. **Research product and packaging.** The inspector, portable executable, hosted container, artifact integrity and reproducible demo add a usable product around the research engine.
2. **Live input support.** Commits `372d0d0` and `f538609` connect Alpaca minute bars to forecast requests and add validation and forecast visibility. This closes the implementation gap previously described as “Not connected yet.”
3. **Market dashboard.** Commits `1273e4c`, `992c503` and `e8dc7d0` add crypto observation, global catalogues and forex reference analytics. These are broader market-information features. They do not by themselves train or validate a stock, crypto or FX forecasting model.

The useful distinction is between engineering completeness, data availability and model validity. More market screens improve observation; reliable forecasts still require matched historical data, training, out-of-sample evaluation and operational acceptance.

## Live forecast contract

On `/forecast`, select **Live streaming price feed** and a compatible model and dataset. Both must use `1m` bars, the requested training symbol, and the feed-specific source `alpaca:iex:first_publication` or `alpaca:sip:first_publication`.

The API requires a connected IEX/SIP stream and a completed regular-session minute bar whose close and availability times are no more than two minutes old. Test, delayed, empty and stale inputs are rejected. The inference buffer retains at most 300 bars per symbol. Duplicates and revisions cannot replace original inputs; missing or late minutes and reconnects reset the window.

Recorded history can be prepended only when it joins the live window without a session-minute gap. Otherwise the stream must accumulate enough bars for feature warmup and model lookback. There is no hidden backfill. New bars and disconnects clear cached forecasts. Inference is requested by the user, not continuously scheduled trading.

Implementation references: `rust/api/src/live.rs`, `rust/api/src/forecast.rs`, `web/src/components/Forecast.tsx` and `web/src/components/Live.tsx`. Operational guide: `Docs/19-LIVE-INGESTION.md`.

## Verification and open risks

This handover is a source, documentation and Git inspection. No full build, test suite, provider connection, deployment smoke test or model-quality study was run for this document.

`Docs/19-LIVE-INGESTION.md` records a 11 November follow-up with 24 API unit tests, 3 API contract tests, 19 data unit tests, 4 point-in-time property tests, 14 frontend unit tests and 24 focused browser checks passing. It explicitly says real Alpaca connectivity, entitlement and live model inference were not verified. Those historical results do not certify every later commit.

The broader production checklist still has open host shutdown/SSE acceptance, provider authentication and market-hours validation, sustained load measurement, supervision/alerts/retention, restart/restore and real-data out-of-sample gates. Some checklist entries are stale implementation descriptions; unchecked operational acceptance must not be silently treated as completed.

The default deployed artifact set is documented as synthetic historical AAPL with real ONNX inference. Synthetic inference execution is not evidence of market predictive quality. Free forex reference series provide descriptive analytics, not OHLCV training inputs or a newly trained FX model.

.\rust\target\debug\quantctl.exe data verify-capture --journal datasets/live/SESSION_ID

The Twelve Data public snapshot path is separately gated by `TWELVE_DATA_API_KEY` and `TWELVE_DATA_PUBLIC_DISPLAY=1`; confirm display permission before enabling it.
